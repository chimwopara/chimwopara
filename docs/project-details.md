# Feature-led project documentation

The source inventory contains 113 entries with feature lists, engineering considerations, build descriptions, and stack information. Entries include whole products and individual tools or sections; counts are not claims of independently deployed products.

Source data:
- src/project-details.js: build profiles and local-source references.
- src/project-features.js: feature lists and capability-group rules.
- src/wopara-data.js: Wopara inventory.
- src/portfolio-data.js: original projects and fashion collection.

Reviewed source includes Wopara's Blob renderers, Spaceship editor registries, Opaline imports, product section renderers, game entry points, and local sibling project repositories. Swift sources support the church app and Family Verifier profiles.

Engineering considerations explain constraints visible in the implementation. They are not invented accounts of personal struggle, measured performance, or verified production reliability. Unavailable source is explicitly distinguished from reviewed implementations. Historical scope and contribution statements come from the original portfolio.

Fashion, branding, and writing are described as those disciplines. No software stacks were invented for them. The historical Roblox Plummet remains separate from Wopara's Three.js game.

Feature labels summarize supported behavior; they do not represent an exhaustive production audit. Planned items in SERVANT.md were not imported as shipped features.

Visitor-facing copy is applied by src/feature-explanations.js after the technical profiles. src/project-catalog.js then consolidates these profiles into 76 displayed entries; see project-catalog.md for the current boundaries and ranking. All 113 entries have sentence-level feature explanations. Product introductions define unfamiliar Wopara names, and example uses are illustrative workflows based on the described functionality. They are not customer stories or claims of measured outcomes.
